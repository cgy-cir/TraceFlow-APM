# TraceFlow 事件协议 v1

> 本文定义 Web SDK 与采集服务之间的稳定契约。MVP 首先实现 `page_view`、`error` 和 `http`；M3 在不升级 `schemaVersion` 的前提下增加 `performance` 和 `resource`，字段见《性能事件协议 v1》。

## 1. 设计目标

- 批量传输，减少请求数量和重复字段。
- 使用判别联合保证不同事件的 `payload` 可校验。
- 允许单批部分成功，坏事件不阻塞同批其他事件。
- 默认最小化采集，避免密码、令牌、Cookie 和请求正文进入平台。
- 协议可向后兼容演进，不让 SDK 与服务端版本强绑定。

## 2. 传输约定

| 项目 | 约定 |
| --- | --- |
| Endpoint | `POST /api/v1/events/batch` |
| Content-Type | `application/json`；Beacon 可使用 `text/plain;charset=UTF-8` |
| 编码 | UTF-8 |
| 成功状态 | `200 OK`，以响应中的逐条结果为准 |
| 鉴别应用 | 请求体批次级 `appKey` |
| 客户端时间 | Unix Epoch 毫秒 |
| ID | UUID v4，小写且带连字符 |
| 单批事件数 | `1..50` |
| 单事件大小 | 不超过 64 KiB |
| 单批请求体 | 不超过 512 KiB |
| 超时建议 | 5 秒 |

`appKey` 是公开的应用标识，不是秘密凭证。服务端还需要校验应用状态、Origin 白名单、请求大小和应用级限流。

## 4. 公共事件结构

```ts
interface TraceEventBaseV1 {
  eventId: string;
  type: 'page_view' | 'error' | 'http' | 'performance' | 'resource';
  timestamp: number;
  sessionId: string;
  anonymousId?: string;
  environment: string;
  release?: string;
  traceId?: string;
  page: PageContext;
  user?: UserContext;
  device?: DeviceContext;
  tags?: Record<string, string>;
  breadcrumbs?: Breadcrumb[];
}
```

| 字段 | 必填 | 限制 | 说明 |
| --- | --- | --- | --- |
| `eventId` | 是 | UUID v4 | 幂等键，同一应用内唯一 |
| `type` | 是 | 枚举 | 决定 `payload` 结构 |
| `timestamp` | 是 | 正整数 | 事件在浏览器中发生的时间 |
| `sessionId` | 是 | UUID v4 | 当前标签页会话 |
| `anonymousId` | 否 | 最长 64 | 浏览器匿名 ID，可配置关闭 |
| `environment` | 是 | 最长 40 | 建议 production/staging/development |
| `release` | 否 | 最长 100 | 必须与 Source Map 版本一致 |
| `traceId` | 否 | 最长 64 | 与后端链路或业务日志关联 |
| `page` | 是 | 见下文 | 事件发生页面 |
| `user` | 否 | 见下文 | 业务方显式设置的最小用户信息 |
| `device` | 否 | 见下文 | 浏览器环境 |
| `tags` | 否 | 最多 20 项 | 自定义检索标签 |
| `breadcrumbs` | 否 | 最多 50 项 | 事件发生前的操作上下文 |

时间容差：服务端允许事件时间比接收时间最多晚 5 分钟、早 7 天。超出范围的事件以 `INVALID_TIMESTAMP` 拒绝，不能悄悄改写原时间。

### 4.1 页面上下文

```ts
interface PageContext {
  url: string;
  path: string;
  title?: string;
  referrer?: string;
}
```

- `url`、`referrer` 最长 2048 字符，服务端再次执行查询参数脱敏。
- `path` 最长 1024 字符，不包含 origin。
- URL 只允许 `http`/`https`；本地开发允许 `localhost`。

### 4.2 用户上下文

```ts
interface UserContext {
  id: string;
}
```

v1 仅接受不可直接识别个人身份的业务用户 ID，不接收邮箱、手机号、姓名和 IP。服务端可从网络层得到 IP，但 MVP 不持久化完整 IP。

### 4.3 设备上下文

```ts
interface DeviceContext {
  userAgent?: string;
  language?: string;
  screenWidth?: number;
  screenHeight?: number;
  viewportWidth?: number;
  viewportHeight?: number;
}
```

尺寸字段必须是 `0..20000` 的整数。浏览器、操作系统等派生字段由服务端后续解析，不由 SDK 同时上传两份可能冲突的数据。

### 4.4 面包屑

```ts
interface Breadcrumb {
  timestamp: number;
  category: 'navigation' | 'ui.click' | 'http' | 'console' | 'custom';
  level: 'debug' | 'info' | 'warning' | 'error';
  message?: string;
  data?: Record<string, string | number | boolean | null>;
}
```

MVP 允许发送空数组；面包屑采集在 M2 完善。`message` 最长 500 字符，`data` 最多 20 项且不允许嵌套对象。

## 5. Page View 事件

```ts
interface PageViewEventV1 extends TraceEventBaseV1 {
  type: 'page_view';
  payload: {
    navigationType: 'initial' | 'push' | 'replace' | 'pop';
    from?: string;
    to: string;
  };
}
```

- 首次加载使用 `initial`，其余值对应 History API 操作。
- `from` 和 `to` 保存站内 path + query，并执行敏感参数脱敏。
- SDK 对相同 `to` 在 300 毫秒内的重复通知去重。

## 6. Error 事件

```ts
interface ErrorEventV1 extends TraceEventBaseV1 {
  type: 'error';
  payload: {
    mechanism: 'onerror' | 'unhandledrejection' | 'resource' | 'manual';
    name: string;
    message: string;
    stack?: string;
    filename?: string;
    lineno?: number;
    colno?: number;
    handled: boolean;
    resourceType?: string;
  };
}
```

| 字段 | 限制/说明 |
| --- | --- |
| `name` | 最长 100；未知时使用 `Error` |
| `message` | 必填，最长 2000；非 Error rejection 需安全序列化 |
| `stack` | 最长 32 KiB；保持原始堆栈供 Source Map 使用 |
| `filename` | 最长 2048 |
| `lineno`、`colno` | 非负整数 |
| `handled` | 全局监听捕获通常为 `false` |
| `resourceType` | 仅 resource 使用，如 script、img、link |

资源加载错误无 JavaScript stack。服务端根据 `mechanism + filename + resourceType` 形成单独的指纹策略。

## 7. HTTP 事件

```ts
interface HttpEventV1 extends TraceEventBaseV1 {
  type: 'http';
  payload: {
    transport: 'fetch' | 'xhr';
    method: string;
    url: string;
    status?: number;
    duration: number;
    outcome: 'success' | 'failure' | 'aborted';
    errorMessage?: string;
    requestSize?: number;
    responseSize?: number;
  };
}
```

- `method` 统一转为大写，最长 16。
- `url` 最长 2048，必须脱敏；不得保存 Authorization 或请求体。
- `status` 为 `100..599`；网络错误没有状态码。
- `duration` 单位毫秒，有限数字且 `>= 0`，保留最多 3 位小数。
- 默认 `200..399` 为 success，`400..599` 和网络异常为 failure，主动取消为 aborted。
- 上报 endpoint 必须进入 SDK denylist，避免递归采集。

## 8. 响应协议

```ts
interface EventBatchResponseV1 {
  requestId: string;
  accepted: number;
  rejected: number;
  errors: EventRejection[];
}

interface EventRejection {
  index: number;
  eventId?: string;
  code: RejectionCode;
  message: string;
}
```

```json
{
  "requestId": "19d890f0-5d98-46d8-8ff6-f49bac42e635",
  "accepted": 2,
  "rejected": 1,
  "errors": [
    {
      "index": 2,
      "eventId": "18f976e0-13e2-4788-9846-a3db3af14cd4",
      "code": "INVALID_PAYLOAD",
      "message": "error.payload.message is required"
    }
  ]
}
```

| Code | 含义 | SDK 行为 |
| --- | --- | --- |
| `UNSUPPORTED_SCHEMA` | 不支持协议版本 | 不重试 |
| `INVALID_EVENT_ID` | ID 缺失或格式错误 | 不重试 |
| `DUPLICATE_EVENT` | 事件已接收 | 视为完成 |
| `INVALID_TIMESTAMP` | 事件时间超出范围 | 不重试 |
| `INVALID_TYPE` | 未知事件类型 | 不重试 |
| `INVALID_PAYLOAD` | payload 与 type 不匹配 | 不重试 |
| `EVENT_TOO_LARGE` | 单事件超限 | 不重试 |
| `RATE_LIMITED` | 应用达到速率限制 | 按响应建议退避 |

HTTP 级错误：

| 状态 | 场景 | 是否重试 |
| --- | --- | --- |
| `400` | 批次 JSON、顶层字段或请求体格式无效 | 否 |
| `403` | 应用禁用或 Origin 不允许 | 否 |
| `404` | `appKey` 不存在 | 否 |
| `413` | 整个请求体超限 | 拆批后最多重试一次 |
| `429` | 应用级限流 | 遵循 `Retry-After` |
| `500/503` | 服务端暂时失败 | 指数退避重试 |

## 9. 幂等与顺序

- 服务端以 `(application_id, event_id)` 唯一索引保证最终幂等。
- `batchId` 用于日志排查，不作为事件幂等键。
- 服务端不保证不同批次按发送顺序处理，展示和聚合以 `timestamp` 为准。
- 重复事件返回 `DUPLICATE_EVENT`，SDK 应从重试队列删除。

## 10. 脱敏规则

默认移除或替换以下信息：

- 查询参数名匹配 `token`、`access_token`、`code`、`password`、`secret`、`authorization`、`session`。
- URL 中的用户名和密码部分。
- Header、Cookie、LocalStorage 和 SessionStorage 内容。
- Fetch/XHR 请求体和响应体。
- 输入框值、DOM 文本和剪贴板内容。

查询参数保留键并将值替换为 `[Filtered]`，便于判断请求形态。SDK 执行第一次过滤，服务端必须再次过滤，不能信任客户端。

## 11. 类型与版本演进

最终 TypeScript 类型为：

```ts
type TraceEventV1 =
  | PageViewEventV1
  | ErrorEventV1
  | HttpEventV1
  | PerformanceEventV1
  | ResourceEventV1;
```

通过 `type` 缩窄 `payload`。Performance 和 Resource 的具体结构见《性能事件协议 v1》。SDK、Demo 和 Console 的共享包使用同一套类型；Java 服务端使用对应 DTO 和基于 `type` 的校验器，不能直接把任意 JSON 无校验写入数据库。

- 新增可选字段时不升级 `schemaVersion`。
- 新增事件类型时，服务端先部署兼容能力，再发布 SDK。
- 删除字段、修改语义/单位或将可选字段改为必填时升级协议版本。
- 服务端至少保留当前版本和前一个主版本的接收能力。
- 原始事件保存接收时的 `schema_version`。

## 12. v1 验收清单

- 基础三种事件都有合法、边界和非法样例测试；M3 扩展类型按《性能事件协议 v1》单独验收。
- TypeScript 类型、Java DTO 和本文字段一致。
- 同一 `eventId` 重发不会产生重复记录或重复聚合。
- 一条坏事件不会阻止同批其他合法事件写入。
- URL 敏感查询参数在 SDK 和服务端均被过滤。
- 上报地址不会被 HTTP 插件再次采集。
- Beacon 的 `text/plain` 请求也经过相同校验流程。
