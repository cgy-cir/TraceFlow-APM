# TraceFlow 性能事件协议 v1

> 本文是《事件协议 v1》的向后兼容扩展，定义 M3 新增的 `performance` 和 `resource` 事件。批次 endpoint、公共上下文、时间、幂等、脱敏和响应规则继续遵循《事件协议 v1》。

## 1. 版本策略

- `EventBatchV1.schemaVersion` 保持 `1`。
- 服务端先支持新事件类型，再发布包含采集能力的 SDK。
- 旧 SDK 不发送新类型，仍可正常工作。
- 旧服务端会以 `INVALID_TYPE` 拒绝新类型，因此不能先发布 SDK。
- 修改单位、必填性或既有字段语义时才考虑协议主版本升级。

扩展后的联合类型：

```ts
type TraceEventV1 =
  | PageViewEventV1
  | ErrorEventV1
  | HttpEventV1
  | PerformanceEventV1
  | ResourceEventV1
```

## 2. Performance 事件

Performance 事件包含两种 payload：Web Vital 和 Navigation Timing。

```ts
interface PerformanceEventV1 extends TraceEventBaseV1 {
  type: 'performance';
  payload: WebVitalPayloadV1 | NavigationTimingPayloadV1;
}
```

performance 事件不携带 breadcrumbs，避免高频指标重复复制诊断上下文。

### 2.1 Web Vital

```ts
interface WebVitalPayloadV1 {
  kind: 'web_vital';
  metricName: 'LCP' | 'CLS' | 'INP' | 'FCP' | 'TTFB';
  measurementId: string;
  value: number;
  delta: number;
  unit: 'ms' | 'score';
  rating: 'good' | 'needs-improvement' | 'poor';
  navigationType:
    | 'navigate'
    | 'reload'
    | 'back-forward'
    | 'back-forward-cache'
    | 'prerender'
    | 'restore'
    | 'soft-navigation'
    | 'other';
  attribution?: WebVitalAttributionV1;
}
```

字段规则：

| 字段 | 必填 | 限制 | 说明 |
| --- | --- | --- | --- |
| `kind` | 是 | 固定 `web_vital` | payload 判别字段 |
| `metricName` | 是 | 枚举 | 指标名大写 |
| `measurementId` | 是 | 1..100 字符 | 官方库生成的指标实例 ID |
| `value` | 是 | 有限数，`>= 0` | 指标最终值 |
| `delta` | 是 | 有限数，`>= 0` | 相对上次报告的变化量 |
| `unit` | 是 | 枚举 | CLS 必须为 score，其余必须为 ms |
| `rating` | 是 | 枚举 | 直接使用官方库结果 |
| `navigationType` | 是 | 枚举 | 指标关联的导航类型 |
| `attribution` | 否 | 最多 20 项 | 仅允许下文白名单键和值类型 |

数值最多保留 4 位小数。服务端允许更高精度输入，但入库时统一为 `DECIMAL(16,4)`；超出范围而不能表示时拒绝，不能截断为错误数值。

示例：

  },

    "kind": "web_vital",

### 2.2 Attribution

```ts
interface WebVitalAttributionV1 {
  target?: string;
  resourceUrl?: string;
  interactionType?: string;
  timeToFirstByte?: number;
  resourceLoadDelay?: number;
  resourceLoadDuration?: number;
  elementRenderDelay?: number;
  largestShiftTime?: number;
  largestShiftValue?: number;
  inputDelay?: number;
  processingDuration?: number;
  presentationDelay?: number;
}
```

规则：

- 不同指标只发送与其相关的字段，多余字段由服务端拒绝或移除。
- `target` 最长 256，不包含 DOM 文本和输入值。
- `resourceUrl` 最长 2048，必须是脱敏后的 http/https URL。
- `interactionType` 最长 40。
- 所有 timing 数值必须有限且 `>= 0`。
- attribution 不接受嵌套对象、数组和官方对象原始序列化结果。
- M3 不上传 PerformanceEntry、Node、EventTarget 或 Long Animation Frame 明细。

### 2.3 Navigation Timing

```ts
interface NavigationTimingPayloadV1 {
  kind: 'navigation';
  navigationType: 'navigate' | 'reload' | 'back-forward' | 'prerender' | 'other';
  redirectCount: number;
  dns: number;
  tcp: number;
  tls: number;
  request: number;
  response: number;
  domInteractive: number;
  domContentLoaded: number;
  load: number;
  transferSize?: number;
  encodedBodySize?: number;
  decodedBodySize?: number;
}
```

| 字段 | 单位 | 规则 |
| --- | --- | --- |
| `redirectCount` | count | `0..100` 整数 |
| `dns` | ms | `domainLookupEnd - domainLookupStart` |
| `tcp` | ms | `connectEnd - connectStart` |
| `tls` | ms | 有 TLS 时 `connectEnd - secureConnectionStart`，否则 0 |
| `request` | ms | `responseStart - requestStart` |
| `response` | ms | `responseEnd - responseStart` |
| `domInteractive` | ms | 相对 time origin |
| `domContentLoaded` | ms | `domContentLoadedEventEnd` |
| `load` | ms | `loadEventEnd` |
| Size 字段 | bytes | 非负整数；不可见时省略 |

所有耗时必须是有限数且 `>= 0`，最多保留 3 位小数。Navigation 事件不设置 `measurementId`，每个文档生命周期最多发送一次，并依赖 eventId 幂等。

示例：

```json
{
  "kind": "navigation",
  "navigationType": "reload",
  "redirectCount": 0,
  "dns": 4.2,
  "tcp": 12.8,
  "tls": 8.1,
  "request": 180.4,
  "response": 31.6,
  "domInteractive": 845.7,
  "domContentLoaded": 912.2,
  "load": 1234.5,
  "transferSize": 48211,
  "encodedBodySize": 47600,
  "decodedBodySize": 151204
}
```

## 3. Resource 事件

```ts
interface ResourceEventV1 extends TraceEventBaseV1 {
  type: 'resource';
  payload: {
    url: string;
    initiatorType: string;
    startTime: number;
    duration: number;
    transferSize?: number;
    encodedBodySize?: number;
    decodedBodySize?: number;
    sizeAvailable: boolean;
    nextHopProtocol?: string;
    renderBlockingStatus?: 'blocking' | 'non-blocking';
  };
}
```

字段规则：

| 字段 | 必填 | 限制 |
| --- | --- | --- |
| `url` | 是 | 脱敏 http/https URL，最长 2048 |
| `initiatorType` | 是 | 1..40 字符，如 script/img/css/fetch/xmlhttprequest |
| `startTime` | 是 | 有限数，`>= 0`，相对 time origin 的毫秒 |
| `duration` | 是 | 有限数，`>= 0`，毫秒 |
| Size 字段 | 否 | 非负安全整数，最大 `Number.MAX_SAFE_INTEGER` |
| `sizeAvailable` | 是 | 是否能够可靠读取 size |
| `nextHopProtocol` | 否 | 最长 40，如 h2/h3/http/1.1 |
| `renderBlockingStatus` | 否 | 浏览器支持时发送 |

resource 事件不携带 breadcrumbs。一个页面最多发送 200 条，SDK 默认限制为 50 条。Collector URL 必须过滤。

示例：

```json
{
  "eventId": "58fcf769-d55a-4df5-b0b9-733f87f35f90",
  "type": "resource",
  "timestamp": 1791234567123,
  "sessionId": "a2e10c1f-7f08-4819-a430-fb7c9c5ed7b3",
  "environment": "production",
  "release": "demo-web@1.1.0",
  "page": {
    "url": "https://demo.example.com/orders/1001",
    "path": "/orders/1001"
  },
  "payload": {
    "url": "https://cdn.example.com/assets/orders-a1b2c3.js",
    "initiatorType": "script",
    "startTime": 38.12,
    "duration": 486.32,
    "transferSize": 84021,
    "encodedBodySize": 83211,
    "decodedBodySize": 241902,
    "sizeAvailable": true,
    "nextHopProtocol": "h2",
    "renderBlockingStatus": "blocking"
  }
}
```

## 4. 服务端字段抽取

| 事件 | payload 字段 | `events` 列 |
| --- | --- | --- |
| performance | kind | `performance_kind` |
| web_vital | metricName | `metric_name` |
| web_vital | measurementId | `measurement_id` |
| web_vital | value | `metric_value` |
| web_vital | unit | `metric_unit` |
| web_vital | rating | `metric_rating` |
| resource | url | `resource_url` |
| resource | initiatorType | `resource_type` |
| resource | duration | `resource_duration_ms` |

Navigation 的多个数值保留在 payload JSON，并由聚合任务拆成独立 metric name。原始 payload 和 context 仍完整保存。

## 5. 聚合映射

| 原始数据 | 聚合 metric name | 单位 |
| --- | --- | --- |
| Web Vital | LCP / CLS / INP / FCP / TTFB | ms 或 score |
| Navigation | NAV_DNS / NAV_TCP / NAV_TLS | ms |
| Navigation | NAV_REQUEST / NAV_RESPONSE | ms |
| Navigation | NAV_DOM_INTERACTIVE / NAV_DCL / NAV_LOAD | ms |
| Resource | RESOURCE_DURATION | ms |
| Resource | RESOURCE_TRANSFER_SIZE | bytes |

所有名称由服务端枚举生成，不接受客户端自定义 metric name。

## 6. 去重语义

- 所有事件先按 `(application_id, event_id)` 去重。
- Web Vital 再按 `(application_id, metric_name, measurement_id)` 去重。
- 同一 measurementId 重复到达时视为重复样本，不更新已聚合数值。
- SDK 不使用 `reportAllChanges`，因此 M3 不支持同一 measurement 的修订语义。
- Resource 与 Navigation 只使用 eventId 幂等。

## 7. 兼容与错误响应

沿用 v1 错误码：

- 未部署 M3 的服务端返回 `INVALID_TYPE`。
- metric 枚举、单位、rating 或 navigationType 错误返回 `INVALID_PAYLOAD`。
- NaN、Infinity、负数或超范围数值返回 `INVALID_PAYLOAD`。
- URL 非法或未脱敏仍由服务端清洗；不能安全解析时拒绝。
- 单事件超过 64 KiB 返回 `EVENT_TOO_LARGE`。
- 同一 measurement 重复可返回 `DUPLICATE_EVENT`，SDK 从队列删除。

## 8. 隐私清单

性能事件明确不采集：

- DOM 文本和输入值。
- 完整 CSS selector、随机元素 ID 和任意 data 属性。
- Cookie、Storage、请求/响应 body 和 header。
- 完整 PerformanceEntry 对象。
- Server-Timing 描述和业务后端内部信息。
- 用户 IP、邮箱、手机号和姓名。

允许采集的 URL 全部执行现有敏感 query key 过滤。

## 9. 验收样例

- LCP 2500ms 为 good，2500.0001ms 为 needs-improvement。
- INP 200ms 为 good，500ms 为 needs-improvement，500.0001ms 为 poor。
- CLS 0.1 为 good，0.25 为 needs-improvement。
- INP 无交互时没有事件，而不是 value=0。
- CLS unit=ms 被拒绝。
- LCP value=NaN、Infinity 或负数被拒绝。
- 跨域 size 不可见时 `sizeAvailable=false` 且 size 字段可省略。
- collector resource 被 SDK 过滤。
- 同一 measurementId 重发不增加 bucket sampleCount。
- v1 的 page_view、error、http 行为保持不变。
