# M4 验收与演示

验收日期：2026-10-11。范围为 Release 管理、私有构建产物、生产错误源码定位和首次部署登记；不把本地静态服务当成生产基础设施上线。

## 1. 完成边界

链路：同一次生产构建 → 生成清单和 JS / Map 摘要 → 登录上传 → 全部产物封存 → 生成无 Map 的公共目录 → 静态网站运行 → 登记首次部署 → 真实错误上报 → Console 还原 TSX 源码行列与片段。

- M4.1：版本按应用和大小写精确区分，manifest 不可改，重复创建幂等或冲突。
- M4.2：JS / Map 成对校验、私有 BLOB、草稿删除、配额、幂等重传和完整封存。
- M4.3：逐帧定位、独立 API、有限源码上下文、可解释降级和有界缓存。
- M4.4：首次部署登记、真实生产构建 E2E、现有功能回归、CI 配置和演示资料。

数据库仍是 V7。本轮只使用已有 deployed_at，不重启 MySQL、不改已执行迁移、不清空持久卷。

## 2. 首次部署登记

接口：`PATCH /api/v1/releases/{id}/deployment?applicationId=...`，JSON 为 `{ "deployedAt": 1791710000000 }`。示例值仅展示毫秒单位，实际请求使用真实部署时间。

管理员和 CSRF 缺一不可；成员只读。服务端锁定当前应用的版本行，在事务内检查并登记：

| 条件 | 行为 |
| --- | --- |
| 当前应用没有此版本 | 404 RELEASE_NOT_FOUND |
| 版本仍为草稿 | 409 RELEASE_NOT_FINALIZED |
| 首次登记时间早于封存、非正数、传秒而非毫秒或超过当前时间一分钟 | 400 INVALID_DEPLOYMENT_TIME（缺值或非正数也可由请求校验拒绝） |
| 已登记相同时间 | 200，返回现有记录 |
| 已登记不同时间 | 409 DEPLOYMENT_CONFLICT，不覆盖 |

UI 使用本地日期时间输入，提交时转为 epoch milliseconds。首次记录不可改；封存和首次部署显示为不同字段。“未登记”不等于“未部署”：系统没有主动检查外部部署状态。

登记只记录发布事实，不会复制文件、启动服务器或实现 CI/CD。多个环境共用同一构建时仍仅记录首次时间，多环境部署历史属于后续功能。

## 3. 从环境启动到完整演示

Windows 在项目根目录安装依赖并启动已有基础设施：

```powershell
cd 'C:\TraceFlow APM'
npm ci
docker compose -f .\deploy\docker-compose.yml up -d mysql
```

默认后端端口 18080，Console 5173，Demo 5174。已有服务可以复用，但后端必须重新运行包含 M4 的代码；旧进程仅通过健康检查并不能证明新接口已经加载。运行中的数据库不需要重启。

完整本地回归：

```powershell
npm run lint
npm test
npm run build
cd server
$env:TRACEFLOW_RUN_DB_TESTS = 'true'
.\mvnw.cmd --batch-mode --no-transfer-progress test
Remove-Item Env:TRACEFLOW_RUN_DB_TESTS
cd ..
# 有 Edge 可复用；没有则运行 npx playwright install chromium，并不设置 channel。
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run test:e2e
```

只重新生成 M4 真实构建演示：

```powershell
npm run test:e2e -- e2e/m4-source-map-upload.spec.ts --grep 'M4.4'
```

Playwright 自动启动未运行的后端、Console 和 Demo。使用自定义端口时要事先启动对应服务并配置匹配的代理、SDK 上报地址和 CORS；环境变量不能让旧后端热加载新 Java 类。

当前工作区隔离预览使用已有的 18082 / 5186，可在本轮预览服务运行期间使用：

```powershell
$env:TRACEFLOW_API_BASE = 'http://localhost:18082/api/v1'
$env:TRACEFLOW_CONSOLE_BASE = 'http://localhost:5186'
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run test:e2e -- e2e/m4-source-map-upload.spec.ts --grep 'M4.4'
```

测试默认使用开发管理员；改过密码请通过 `TRACEFLOW_E2E_EMAIL` / `TRACEFLOW_E2E_PASSWORD` 提供有效账号。不要提交凭证。

## 4. 测试实际做了什么

1. 新建独立 `Z M4 Production ...` 应用，允许本轮随机静态服务 origin，不修改原 Demo 配置。
2. 用 `/m4/` base 做真实 Vite 压缩构建，release 唯一，SDK 上报指向该应用。
3. CLI 上传同一次构建并封存，再重复执行，确认没有第二个版本或重复计数。
4. 生成公共目录，运行独立 HTTP 静态服务；访问 `.map` 和私有 metadata 得到 404。
5. 浏览器加载压缩页面，触发手动错误并真实上报。
6. 管理员 UI 登记首次部署，检查时间校验、请求毫秒值、刷新持久化及同值 / 不同值重试。
7. 定位到 App.tsx 中真实 captureException 调用行；使用独立 JavaScript consumer 比对原始行列。
8. 查询前后核对原始事件、fingerprint、eventCount 不变，检查跨应用读取被拒绝。
9. 查看源码 / 原始堆栈切换，保存桌面和 320px 移动端截图，检查页面无水平溢出。

浏览器 E2E 的独立应用、事件和封存版本保留用于演示，不删除已有业务数据。临时静态服务结束时关闭，因此样例中的原 pageUrl 不会一直在线；Console 读取数据库中的事件和 Map 仍可定位。每次重新跑 Playwright 会重建 test-results，重要演示证据可由 CI artifact 保留。

## 5. 演示材料

本轮生产测试目录名以 `test-results/m4-source-map-upload-M4-4-` 开头。目录中包含：

- `source-stack-example.json`：本轮应用 / 版本 / Issue / 事件 ID，版本详情及错误详情地址，毫秒部署时间、产物量和各阶段耗时。
- `deployed-release-desktop.png`：封存与首次部署两个独立时间字段。
- `deployment-mobile.png`：移动端登记表单。
- `source-stack-desktop.png` / `source-stack-mobile.png`：真实源码片段。
- `public/`：本轮静态服务用公共资源，无 Map 和私有 manifest。

可快速找到最新地址：

```powershell
$example = Get-ChildItem -LiteralPath .\test-results -Recurse -Filter source-stack-example.json |
  Sort-Object LastWriteTime -Descending | Select-Object -First 1
Get-Content -LiteralPath $example.FullName
```

展示顺序建议：先看版本详情的完整产物和封存时间，再看首次部署时间，最后打开 issueUrl，切换压缩堆栈与 TSX 源码，说明同一次构建和路径 / release 匹配如何建立可信定位。缺第三方 Map 导致 partial 是正常诊断，不冒充全部还原。

## 7. CI 与剩余边界

CI 已配置 frontend lint / test / build、Java 单元测试、MySQL 8.4 集成测试及完整浏览器 E2E。生产构建用真实静态服务，不用 Vite dev server 替代压缩堆栈验收。失败保留 trace，工作流上传 Playwright 报告与 test-results，保留七天。

本轮未提交或推送，不能声称远程 Linux CI 已通过。M4 本地功能关闭不等于 M6 生产上线；Linux 部署、Nginx、HTTPS、生产凭证、数据库备份恢复和在线演示地址仍需后续验收。Firefox / Safari stack parser、indexed Maps、多环境部署历史和远程源码读取不在首轮支持范围。
