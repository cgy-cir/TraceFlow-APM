# M4.2 构建产物上传与发布

本文记录 M4.2 版本产物管理，复用 V7 的 `releases` / `source_maps`，没有 V8 迁移。后续 M4.3 已完成错误堆栈还原，使用说明见《M4源码定位与诊断》。

## 1. 已实现能力

- 在版本详情中成对上传 JS 与 Map，展示上传状态和有源码内容的文件数量。
- 草稿产物可以删除，删除后同步扣减计数和 Map 总量。
- 全部清单产物上传成功才能封存，封存与上传 / 删除共用版本行锁。
- 同一路径、同一摘要重传返回现有产物；封存后也允许这种幂等重传。
- 封存后不能新增、替换或删除产物。版本名称和 manifest 仍保持不可变。
- 后端重新计算 JS / Map 字节摘要，不信任客户端提供的文件名、类型或摘要。
- Source Map 存在 MySQL 私有 BLOB 中，列表仅返回元数据，不提供公开下载接口。
- 解析使用固定 `closure-compiler:v20240317` 的 SourceMapConsumerV3，不手写 VLQ。依赖 consumer 的 class 字节码版本已在测试中检查不高于 Java 17。

M4.2 当时的验收范围仅为上传、保存和封存，不把“能解析 Map”当作完整事件还原。后续 M4.3 已单独通过真实生产事件的逐帧还原与源码位置验收。

## 2. 限制和校验

| 项目 | 当前上限 |
| --- | ---: |
| 单个 JS / Map | 各 5 MiB |
| multipart 总请求 | 11 MiB |
| 单版本产物数 / Map 总量 | 100 个 / 100 MiB |
| 同时校验上传 | 2 个，容量满直接返回 429 |
| JSON 深度 | 20 |
| sources / names | 各 20,000 项 |
| 映射段 / 生成行数 | 500,000 段 / 200,000 行 |

这些是首轮受测试覆盖的固定上限；只调大 Spring multipart 配置，不会绕过后端单文件检查。生产入口代理也应配置上传大小限制。

只支持有效 UTF-8 Source Map v3 普通映射。indexed `sections` 明确拒绝；不读取远程 source、section URL 或服务器本地源码。可没有 `file` 或 `sourcesContent`；有 `file` 时须等于 JS basename，有 sourcesContent 时须与 sources 等长，元素允许 null。

校验解析和读取文件在事务外完成，进入事务后再次检查版本归属、状态、清单和配额。校验失败不写入大文件，不修改已有产物。

摘要证明的是传输和重复上传的一致性，不能证明 Map 与 JS 的构建配对一定正确。必须使用同一次最终构建的产物，生成 Map 后不能再无映射地改动 JS。

## 3. Demo 私有生产构建

在项目根目录执行。以下以已有开发 Demo 应用为例，后端须运行包含 M4.2 的最新代码。

```powershell
cd 'C:\TraceFlow APM'
$release = 'demo-web@0.2.0+build1'
$env:VITE_TRACEFLOW_ENVIRONMENT = 'production'
$env:VITE_TRACEFLOW_ENDPOINT = 'http://localhost:18080/api/v1/events/batch'
# 新建应用接入时设置其 appKey；已有 Demo 可使用默认值。
# $env:VITE_TRACEFLOW_APP_KEY = '该应用的 appKey'

npm run build:demo:release -- --release $release --url-prefix /
```

此命令依次构建 shared、Web SDK 和 Demo，输出到 `apps/demo/dist-private`，注入 SDK release，并启用 `sourcemap: 'hidden'`。

私有目录内还有 `traceflow-release.json`，记录 release、部署 URL 前缀和构建文件摘要。**该目录不可直接作为网站发布目录。** 下一次私有构建会更新该目录，因此要完成当前版本上传与公共目录生成后再构建下一版。

普通 `npm run build` 仍使用正常 dist，不启用这次私有构建环境；脚本对子进程设置的私有构建标志不会污染父终端。

如果网站部署在 `/traceflow/`，构建、上传、公共目录生成三步都传 `--url-prefix /traceflow/`。首轮脚本要求前缀为不含查询参数、编码、空白或穿越的 ASCII pathname，以 `/` 开始和结束。

构建应覆盖每个 JS chunk，包括动态加载文件。脚本检查缺 JS、缺 Map、符号链接、超限文件和重复参数。JS / Map 字节摘要在本地和服务端各计算一次。

## 4. 上传与封存

```powershell
$env:TRACEFLOW_API_BASE = 'http://localhost:18080/api/v1'
$env:TRACEFLOW_UPLOAD_EMAIL = 'local@traceflow.dev'
# 从安全来源设置当前管理员密码，不提交到仓库。
$env:TRACEFLOW_UPLOAD_PASSWORD = '当前管理员密码'

npm run upload:source-maps -- --application-id 1 --release $release --dist apps/demo/dist-private --url-prefix /

Remove-Item Env:TRACEFLOW_UPLOAD_PASSWORD
```

可增加 `--commit`，要求完整 40 或 64 位十六进制 SHA。同一版本首次创建后，重传必须使用相同 commit 与 manifest；不能第二次才补一个不同 commit。

流程：

1. 扫描本地产物；存在私有构建 metadata 时核对版本、前缀和摘要。
2. 使用管理员邮箱 / 密码登录；Node 脚本显式维护 Session Cookie。
3. 每次写请求前取 CSRF Token，包含登录后 token 轮换。
4. 创建或幂等复用版本，查询已有产物并跳过匹配项。
5. 按顺序上传剩余 JS / Map；超时结果不确定时先查服务端元数据，再重试。
6. 全部上传成功后封存，最后尝试退出上传 Session。

远程地址必须 HTTPS，本地 localhost / 127.0.0.1 / ::1 调试允许 HTTP。脚本拒绝跳转，不把 Cookie 或密码发送到重定向地址。日志不打印凭证、Token 或源码。

网络故障、429 与 5xx 允许有限重试，其他 4xx 直接失败。失败返回非零退出码；不要把“创建了草稿”当成“上传成功”。重复执行相同命令不会生成第二个版本或重复增加产物数量。

若退出登录无法确认，脚本告警，Session 随后按服务端超时失效。

其他网站也可使用该上传脚本，只要产物遵守 JS / Map 配对规则，SDK release 与 `--release` 一致。外部构建没有 TraceFlow metadata 时，脚本无法自动验证 SDK 内嵌版本，调用者必须确保一致。

## 5. 生成公共发布目录

先确认上传命令返回封存成功，再执行：

```powershell
npm run prepare:public -- --release $release --dist apps/demo/dist-private --out apps/demo/dist-public-build1 --url-prefix /
```

输出目录必须不存在，不会删除或覆盖已有目录。公共目录不能放在私有目录内。脚本不自动访问服务器验证封存状态，因此执行顺序仍由发布流程保证。

- 排除所有 `.map` 与 `traceflow-release.json`。
- 拒绝带 sourceMappingURL 的公共 JS，防止误用非 hidden 构建。
- 首轮允许 HTML / JS / CSS、常见图片和字体；遇到未知扩展名明确失败，不自动发布私有文件。
- 拷贝 JS 时重新校验字节摘要，不能上传后重建 JS 再发布。
- 命令失败留下的部分目录不能发布；使用新的输出目录重试。

只有这个命令成功后的公共目录才能交给静态服务或 Nginx。部署后检查 `.map` 和私有 metadata 的 URL 不可访问。`hidden` 仅隐藏 JS 注释，不提供访问权限控制。

## 6. 页面操作和接口

管理员在版本详情每个产物的上传按钮中选择两个文件；摘要不匹配时保留文件选择并展示错误。上传成功后刷新详情、产物列表和版本列表缓存。

草稿缺产物时封存按钮禁用。全部上传后，确认封存不可逆；之后页面不再显示上传或删除按钮，后端也独立限制写操作，不能只依赖按钮隐藏。

| 方法 | 接口 | 返回 |
| --- | --- | --- |
| GET | `/api/v1/releases/{id}/source-maps?applicationId=...` | `{ items: MapSummary[] }`，无完整源码 |
| POST | 同上，multipart | 首次 201 / 幂等 200，返回 MapSummary |
| DELETE | `/api/v1/releases/{id}/source-maps/{mapId}?applicationId=...` | 204，仅草稿 |
| POST | `/api/v1/releases/{id}/finalize?applicationId=...` | ReleaseDetail，重复封存幂等 |
| PATCH | `/api/v1/releases/{id}/deployment?applicationId=...` | `{ deployedAt: 毫秒时间戳 }`，返回 ReleaseDetail |

写接口要求管理员和 CSRF；成员只读。错误码包括 INVALID_SOURCE_MAP、UNSUPPORTED_SOURCE_MAP、ARTIFACT_CONFLICT、RELEASE_INCOMPLETE、RELEASE_FINALIZED、RELEASE_QUOTA_EXCEEDED、UPLOAD_TOO_LARGE、SOURCE_MAP_BUSY。

M4.4 已增加首次部署登记：公共网站实际发布且检查可访问后，管理员在已封存版本详情点击“登记首次部署”，选择浏览器本地时间。接口只接收毫秒时间戳，时间不能早于封存或超过服务器当前时间一分钟。登记后不可修改，同值重试 200，不同值 409 `DEPLOYMENT_CONFLICT`；草稿登记 409 `RELEASE_NOT_FINALIZED`，非法时间 400 `INVALID_DEPLOYMENT_TIME`。

封存不会自动填写 deployedAt，也不代表网站已经部署。上传脚本同样不登记部署时间；登记不是执行部署的接口，不会检查远程网站状态。缺部署登记不阻止已封存版本的源码定位。当前复用 V7 预留的 deployed_at，无新增迁移。

## 7. 验证与测试数据

```powershell
npm run lint
npm test
npm run build

cd server
$env:TRACEFLOW_RUN_DB_TESTS = 'true'
.\mvnw.cmd test
Remove-Item Env:TRACEFLOW_RUN_DB_TESTS

cd ..
# Windows 可复用已安装 Edge，CI 使用安装的 Chromium。
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run test:e2e
```

数据库测试覆盖配额、摘要冲突、删除扣减、幂等封存及真正并发上传的唯一计数；默认关闭，CI MySQL 任务启用。并发测试创建独立用户 / 应用，结束后只清理自己创建的记录，其他数据库测试通过事务回滚。

端到端测试覆盖浏览器上传与文件错误修正，以及真实 Vite 生产构建、CLI Session / CSRF、重复上传、非根 base 路径、Map 公网 404 和真实事件上报。生产测试创建独立 `Z M4 Production ...` 应用，不改变开发 Demo 的 allowedOrigins；测试版本封存后保留，不删除业务版本。公共测试服务在测试结束时关闭。

测试后续已增加 M4.3 / M4.4 校验：由浏览器真实堆栈定位到 App.tsx 源码，用独立 JavaScript consumer 比对行列号，并验证 Console 中的源码 / 原始视图与首次部署登记。可重复演示和实际验收结果见 [M4验收与演示](M4验收与演示.md)。
