# Console 用户登录与管理

## 功能范围

当前 Console 面向一个共享团队。所有启用的账号可以查看同一平台内的应用、错误、请求和性能数据，并处理 Issue。管理员额外拥有创建应用和管理用户的权限。本轮不引入组织、应用成员或跨租户隔离。

- `/login`：邮箱和密码登录，成功后返回原先访问的页面。
- `/users`：管理员查看、搜索、分页、创建和编辑用户，启用或禁用账号，重置密码。
- 顶部账号菜单：查看当前账号、修改自己的密码、退出登录。
- 成员访问用户管理页面时显示权限提示，直接请求管理接口也会收到 403。
- 禁用用户、修改角色、重置密码会使该用户原有会话失效。
- 不提供删除用户，以保留应用所有者和历史记录的引用。

## 本地启动与默认账号

在项目根目录运行 `npm run dev:console`，在 `server` 中运行 `mvnw.cmd spring-boot:run`。已有进程需要重启以加载新的安全配置。Flyway 会自动执行 `V6__add_user_authentication.sql`。

开发环境初始账号：

- 邮箱：`local@traceflow.dev`
- 初始密码：`TraceFlow@2026`
- 角色：管理员。

`TRACEFLOW_DEV_ADMIN_PASSWORD` 可以在开发环境首次初始化前替换初始密码。原来的 `{noop}disabled` 占位密码会被 BCrypt 替换；已有真实密码不会在重启时被覆盖。通过账号菜单修改密码后，以新密码登录。

非开发环境可以在启动前设置 `TRACEFLOW_BOOTSTRAP_ADMIN_EMAIL` 和 `TRACEFLOW_BOOTSTRAP_ADMIN_PASSWORD`。仅在不存在启用的管理员时创建初始管理员；初始化后移除这两个环境变量。

## 登录与权限

使用 Spring Security 的表单认证和服务端 Session。登录接口接收表单编码的 `email`、`password`。密码使用 BCrypt 哈希；API 返回的用户对象不包含密码哈希或会话版本。

浏览器通过 HttpOnly 的 `JSESSIONID` Cookie 携带会话，不将登录凭据写入 localStorage。Session 不活动超时为 30 分钟，Cookie 使用 SameSite=Lax。HTTPS 部署设置 `TRACEFLOW_SECURE_COOKIE=true`。

管理接口的写操作包含 CSRF 校验。Console 每次写请求前获取新的 CSRF Token，因为登录和退出会改变该 Token。`TRACEFLOW_CONSOLE_ORIGINS` 是逗号分隔的 Console Origin 白名单，默认包含 `http://localhost:5173`、`http://localhost:5174`。

SDK 的 `/api/v1/events/batch` 保持公开，继续依赖 App Key 和 Origin 校验，并独立豁免 CSRF。健康检查和 Demo 的不存在资源路径保持公开。其余监控查询要求登录，用户管理和创建应用要求管理员权限。

用户表增加 `role`、`session_version`、`last_login_at`。时间继续使用毫秒时间戳。请求会检查数据库中的账号状态和会话版本，因此不必等 Session 超时，账号权限变更即可生效。

管理员不能修改自己的角色或账号状态，也不能通过管理接口重置自己的密码。事务中锁定启用的管理员记录，避免并发修改导致平台失去管理员。修改自身密码需要验证当前密码，成功后退出当前登录。

## API

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/v1/auth/csrf` | 获取 CSRF Header 名称和 Token |
| POST | `/api/v1/auth/login` | 登录并创建 Session |
| GET | `/api/v1/auth/me` | 当前用户；匿名时无用户数据 |
| POST | `/api/v1/auth/logout` | 退出并清理 Session |
| POST | `/api/v1/auth/password` | 验证当前密码并修改自身密码 |
| GET | `/api/v1/users` | 按姓名、邮箱、角色、状态筛选和分页 |
| POST | `/api/v1/users` | 创建用户 |
| PATCH | `/api/v1/users/{id}` | 修改姓名、角色和状态 |
| POST | `/api/v1/users/{id}/password` | 管理员重置其他用户的密码 |

邮箱创建后保持不变。密码至少 8 个字符，最多 72 个 UTF-8 字节，与 BCrypt 的限制一致。修改账号或登录失败时返回具体错误码；错误密码和禁用账号共用登录失败提示。

## React 实现

- `useCurrentUser` 通过 React Query 共享当前登录用户。
- `AuthGate` 使用 `<Navigate>` 保护页面，在渲染提交时进行导航。
- `http.ts` 统一携带 Cookie、获取 CSRF Token 和处理 401。
- 登录、退出或会话失效时取消请求并清理 QueryClient，避免切换账号后复用其他账号的缓存。
- 创建、编辑和重置操作用 `useMutation`，成功后使用户列表缓存失效。
- 表单校验和确认弹窗均使用 Ant Design；页面布局使用现有 Tailwind CSS。

## 验证与后续

后端安全测试覆盖匿名访问、成员权限、CSRF、有效登录、错误凭据、失效会话和密码字节长度。Playwright 验证页面登录、刷新恢复、退出、用户创建与编辑、密码重置、自身改密、禁用账号和旧会话失效，同时回归 M2/M3。

端到端测试通过 `TRACEFLOW_E2E_EMAIL`、`TRACEFLOW_E2E_PASSWORD` 配置管理员账号，默认使用开发账号。测试创建的 `e2e-user-*` 账号在结束时禁用。

Session 当前存放在单个后端进程的内存中，重启后需要重新登录。多实例部署时再接入共享 Session 存储；组织级权限、密码找回和登录限流需要单独设计。
